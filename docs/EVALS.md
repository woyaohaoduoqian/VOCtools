# VOCtools v2 验收

## 核心场景

| 编号 | 场景 | 必须结果 |
|---|---|---|
| V1 | 模糊需求 | 只生成 intake/research 草案，不做能力检查或采集 |
| V2 | 研究设计 | plan、来源需求和通用查询不含 Provider 操作参数 |
| V3 | 能力匹配 | 配置存在但当前任务未暴露操作时判不可执行 |
| V4 | 采集失败 | 不自动换 Provider、改查询、扩范围、放宽规则或重试明确失败 |
| V5 | 采集质量 | 不依赖主类别或编码文件 |
| V6 | 分析质量 | 编码后检查唯一单位、多维证据、用途所需维度、回复计数和数字复算 |
| V7 | 类别统计 | 只从 analysis-units.csv 计算，支持性回复不进主分母 |
| V8 | 洞察链 | 每条发现按支持证据关联的唯一分析单位复算，并可经 F→E→R 回到公开原文 |
| V9 | 商业边界 | 不把公开付费表达写成购买率、转化、留存或商业影响 |
| V10 | v1 迁移 | 明确迁移并校验记录数、单位数、主类别和链接；迁移后保持阻塞 |
| V11 | 交付 | 平台无关文件的 Schema、字段、行数、哈希和版本全部通过 |
| V12 | 架构边界 | 核心框架无运行操作/鉴权/端点；平台画像无 Provider/接入状态 |
| V13 | 方法完整性 | 来源侦察、逐轮筛选、失败矩阵、饱和度、二次编码、分母和措辞边界均存在 |
| V14 | 接入隔离 | 核心以 INSTRUCTIONS/workflows 存在；Codex 包可生成且仓库不保存生成副本 |
| V15 | 采集追溯 | 缺成功请求、raw 或 R→REQ 映射时采集质量必须失败 |
| V16 | 编码审计 | 缺 codebook CODE 定义、主证据或 10% 二次编码时分析质量必须失败 |
| V17 | 用户确认 | 方案、查询、绑定或采集范围没有有效确认哈希时不得交付 |
| V18 | 采集追溯 | 请求运行、Provider、查询或 raw 响应哈希不一致时采集质量失败 |
| V19 | 采集观察 | 参数、相关性、异常内容或平台偏差未检查时不得进入分析 |
| V20 | 编码复核 | 排除单位、重复单位或最终编码不一致的审计不能满足覆盖率 |
| V21 | 洞察关系 | 每个 `I-` 必须逐卡关联至少一个存在的 `F-` |
| V22 | 阶段状态 | 跳阶段、伪退回或跨阶段写 passed/blocked 必须校验失败 |
| V23 | 报告内容 | 空报告、缺少固定章节或洞察卡章节为空时不得交付 |
| V24 | 结构化输出 | finding 事实/范围/证据为空或 hypothesis 缺少未验证假设/验证方法时不得交付 |
| V25 | 授权范围 | 用途、目标用户、样本、成本、币种或扩样边界与 collection_scope 确认不一致时不得进入分析或交付 |
| V26 | 交付终态 | 未经 finalize 的 running/pending 任务不得打包 |
| V27 | 插件更新 | 每次 Codex 打包生成新的规范 semver cachebuster，且生成物仍不进入 Git |
| V28 | 用途边界 | 角色与方案只声明用户需求、使用体验和产品问题与改进，不宣称尚无研究协议的用途 |
| V29 | 综合质量 | 阶段 8 产物未通过发现复算、证据角色、洞察关系和报告内容检查时不得进入交付 |
| V30 | 查询授权 | 只有 approved/include 查询可以产生正式请求和记录 |
| V31 | 负面交付 | 空质量结果、错误分母或断裂 F→I→H 链必须被拒绝 |

自动回归覆盖初始化、三种正式用途、多维分析、采集/分析/综合质量、交付和 v1 迁移。对真实对话还需用新任务人工验证 V1–V9。
