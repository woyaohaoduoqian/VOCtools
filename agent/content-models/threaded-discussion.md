# threaded-discussion 内容模型

适用于具有主题内容与回复树的公开讨论。模型不绑定具体平台或 Provider。

## 实体与关系

- `thread`：主题内容。
- `reply`：直接或间接回复，使用 `parent_record_id` 关联父记录，并可沿父链回到主题内容。
- 每条记录有稳定 `record_id`、`permalink`、发布时间和采集时间。

## 主分析单位

- 规范化主题内容是主分析单位，一条规范主题只生成一个 `analysis-units.csv` 行。
- 回复是支持证据、反例、上下文或排除依据，不直接进入主题数量和类别分母。
- 每个纳入分析的单位恰有一个 `primary_code`；其他主题写入 `secondary_codes`，不参与主类别分布。

## 去重与排除

1. 优先按平台记录 ID 去重，其次按规范化永久链接。
2. 交叉发布或重复采集保留一个规范主题；其余单位标记重复并记录保留对象。
3. 广告、机器人、超出时间窗和不相关内容保留排除理由，不进入主分母。
4. 缺少稳定 ID 和永久链接时不得自行按相似文本合并，只能标记待审阅。

## 证据关系

`evidence-links.csv` 使用：

- `primary`：构成分析单位的主题内容；
- `supporting`：补充同向细节；
- `counterexample`：提供反例或相反经验；
- `context`：解释场景但不直接支持发现；
- `exclusion_basis`：支持排除决定。

逐字引文必须与对应记录的 `text` 完全匹配并能回到永久链接。

## 计数

- 类别分布只从纳入且去重后的 `analysis-units.csv` 计算。
- 分别报告主题单位数、有效回复数和独立回复作者数；不得相加后称为“条数”。
- 默认不对主题和回复加权。确需权重时在方案中预注册公式、理由和敏感性检查，同时保留未加权分布。
- 样本目标按合格主题单位计算；回复、候选、存疑、排除和重复记录不能补足目标。

## 发布前验证

- `unit_id` 与 `primary_record_id` 唯一；
- 每个纳入单位恰有一个主类别；
- 每个证据链接引用存在的单位和记录；
- 回复不成为主分析单位；
- 主类别数字可从分析单位表复算；
- 反例、排除和覆盖限制没有被丢弃。
