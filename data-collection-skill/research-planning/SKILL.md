# 调研方案规划

用户带着模糊描述来("看看 IG 上美甲哪些达人火"、"用户对 xx 有什么抱怨"),本 skill 负责把它变成一份用户确认过的方案。**方案没确认之前,不碰任何采集工具。**

## 第一步:判断研究模式

先分清用户是哪种入口,两种模式的方案结构不同:

| | 验证式(问题驱动) | 探索式(数据驱动) |
|---|---|---|
| 起点 | 有具体问题或假设("持久度是不是最大痛点") | 只有一个范围("看看这个领域用户在说什么") |
| 方案核心 | 研究问题 + 预先写好的判断标准(看到什么算支持) | 取样说明(范围、平台、词、量)+ 停止条件 |
| 产出承诺 | 对问题的回答(支持/不支持/数据不足) | 发现候选清单,**一律不写成结论** |

探索式的输出(痛点候选)就是验证式的输入,两者是接力不是并列。用户没说清是哪种时,问一句,不要猜。

## 第二步:可答性判定(最重要的拦截点)

不是所有问题都能用爬数据回答。收到需求先过这三道闸:

1. **定性还是定量**:爬虫擅长"是什么、为什么"(痛点内容、用户原话、竞品差评),做不了"有多少"(市场占比、发生率、规模)。凡涉及占比和规模的问题:改问法(改成"样本内声量排序")、或明确告知答不了。
2. **数据通道对不对**:
   - 平台内容(帖子/评论/达人)→ 爬虫采集
   - 行业报告、市场规模、新闻趋势 → 深度搜索/网页检索,不是爬虫
   - 唯一禁止的混用:**拿搜索引擎的零散结果冒充样本做统计**——搜索结果没有分母,任何计数都不成立
3. **平台给不给**:需求落到四元组后查 data-collection 的能力清单。要"转化率""销量"这类平台根本不暴露的字段,直接说拿不到,不承诺。

判不过的需求,给出改写建议或替代问法,让用户选,不硬做。

## 第三步:落成四元组 + 取样说明

把需求翻译成 {起点, 平台, 内容类型, 字段},并显式写出取样选择:

- 去哪个平台、用什么词/账号当起点、采多少条、什么时间范围
- **取样选择就是研究前提**:在哪捞就只能发现哪的东西。方案里必须写一句"本次发现仅覆盖 xx 范围",探索式尤其不可省略

字段选择原则:够用就好,common 档打底,按分析目的加 advanced,不无脑全选(字段越多越贵、表越乱)。

## 第四步:预写判断标准(验证式必做)

在看到数据之前写下:什么样的数据算支持假设、什么算推翻、什么算数据不足。写完给用户确认。这是防"先有数据再圆结论"的关键动作,顺序不能反。【待核对:预注册模板以方法论 v0.3 原文为准】

探索式改为预写**过程标准**:采多少、覆盖哪些来源、什么时候停(见 quality-check 的饱和判定)。

## 方案输出模板

```
## 调研方案(待确认)
- 研究模式:验证式 / 探索式
- 研究问题 / 探索范围:
- 判断标准(验证式)/ 停止条件(探索式):
- 采集任务:起点 × 平台 × 内容类型 × 字段档位
- 取样说明:范围、条数、时间窗;本次发现仅覆盖……
- 预估成本:$xx(明细见采集环节)
- 答不了的部分:……(如有,写明原因)
```

用户确认后,移交 data-collection 执行。
