# 洞察提炼与输出

从数据到结论的规矩。核心原则:**结论强度不得超过证据强度;数据说不了的,明确写"说不了"。**

## 入口条件

同时满足才进入本 skill:

1. quality-check 全量闸门判定为**可用**或**带保留可用**(不可用 → 退回,不写结论)
2. 方案里的产出形式是**发现或结论**

方案只要数据表的任务(达人清单、竞品账号表等),到 quality-check 结束,**不走本 skill**。给一张名单硬配一段"洞察"是画蛇添足。

## 输入

- `plan.md` —— 研究问题、判断标准或停止条件、取样说明、"答不了的部分"
- `quality.md` —— 判定和**保留点**(带保留可用时必须逐条进报告)
- `manifest.json` —— 溯源:数据来自哪个工具、什么参数、什么时候采的
- `processed/*.csv` —— 数据本身

## 编码聚类

对评论、帖子这类文本数据逐条打标归类。**编码结果必须落成文件**,不能只在推理里完成——否则后面的计数无法复算、抽检无法复现。

产出 `coded.csv`:原数据每行追加 `类别` 和 `编码依据` 两列,归不进的填 `未归类`。

- **验证式**:按方案预写的判断标准里的类别归。归不进去的进"未归类"桶,**不硬塞**。类别不得中途新增——那等于改判断标准。
- **探索式**:开放式编码,类别从数据里长出来,边归边长。要求更严:
  - 类别定义随归随写,写进 `codebook.md`(类别名 + 一句话定义 + 纳入排除标准)
  - "未归类"桶必须保留并报告其占比。占比过高(超过三成)说明类别体系不合适,报告并建议重编,不要硬提高覆盖率
  - 完成后**抽 10% 复查归类一致性**,报告不一致的条数。【暂定规则:不一致率超过 20% 时判定编码不可靠,须修订类别定义后重编。此阈值以方法论原文为准,核对后替换】
- **内容形式类研究**(研究"什么内容在火"而非"用户在抱怨什么"):编码维度换成形式和手法(内容结构、开头方式、标签组合),不是痛点分类。

每个类别的产出:类别名 + 定义一句话 + 条数 + 2-3 条典型原声(带原始链接)。

## 证据强弱与措辞挂钩

结论用什么措辞由证据强度决定,**不由叙事需要决定**:

| 证据情况 | 允许的措辞 | 禁止的措辞 |
|---|---|---|
| 样本内计数(有明确分母) | "样本内(N=xx),xx 类共 xx 条,声量最高" | 外推到"市场上""用户普遍" |
| 探索式发现 | "浮现出以下候选""值得进一步验证" | 任何结论式表述 |
| 少量原声(<10 条)支撑的观察 | "有个别用户提到" | "不少用户""普遍反映" |
| 来源集中(quality-check 标注过) | "主要来自 xx 社区/账号,其他来源未见" | 当作全样本共识 |
| 二手转述、检索所得 | 注明来源性质,降级表述 | 与一手样本混用计数 |
| 数据不足以回答 | "本次数据回答不了 xx" | 用推测填补 |

**禁用词清单**(出现即需降级或删除):普遍、大多数、显著、明显趋势、用户认为、市场需求是——除非有明确分母的计数支撑,且分母是本次样本。

**百分比使用规则**:只在分母是本次样本且已在同句写明时使用(如"样本内 120 条中占 35%")。不写分母的百分比一律禁止。

【本节为暂定版本,完整证据强弱表和禁用词清单以方法论原文为准,核对后替换】

## 防编造

- **每条结论挂证据**:结论后跟支撑它的类别、计数或原声引用(带原始链接)。**挂不上证据的句子删掉**,不要保留"看起来对"的判断。
- **引用必须真实**:原声从 `coded.csv` 里逐字取,不得改写、不得合成"典型用户会说"式的虚构引语。引用要能在原数据里搜到。
- **数字必须可复算**:报告里每个数字都用脚本从 `coded.csv` 重算一遍再写入。不得手工估算或凭印象写。
- **区分事实与解读**:结构上分开"数据显示什么"(事实)和"这可能意味着什么"(解读),解读段明确标注为解读,且解读不得引入数据里没有的新事实。
- **保留点不得弱化**:quality.md 里的保留点原样进报告,不许改写成更好听的说法、不许省略、不许挪到末尾。
