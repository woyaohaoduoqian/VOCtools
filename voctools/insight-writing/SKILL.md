# 洞察提炼与输出

从数据到结论的规矩。核心原则:**结论强度不得超过证据强度;数据说不了的,明确写"说不了"。**

## 编码聚类(定性数据的整理方法)

对评论/帖子这类文本数据,逐条打标归类("这条在抱怨持久度、那条在问价格"):

- **验证式**:按预写的判断标准里的类别归;归不进去的进"无法归类"桶,不硬塞。
- **探索式**:开放式编码,类别从数据里长出来,边归边长。要求更严:类别定义要随归随写;"无法归类"桶必须保留;完成后抽 10% 复查归类一致性。【待核对:一致率抽检的具体阈值以方法论 v0.3 原文为准】
- 每个类别的产出:类别名 + 定义一句话 + 条数 + 2-3 条典型原声(带链接)。

## 证据强弱与措辞挂钩

结论用什么措辞,由证据强度决定,不由叙事需要决定:

| 证据情况 | 允许的措辞 | 禁止的措辞 |
|---|---|---|
| 样本内计数结果(有明确分母) | "样本内(N=xx),xx 类声量最高,占 xx 条" | 外推到"市场上/用户普遍" |
| 探索式发现 | "浮现出以下候选""值得进一步验证" | 任何结论式表述 |
| 少量原声(<10 条)支撑的观察 | "有个别用户提到" | "不少用户""普遍反映" |
| 搜索引擎/二手转述来源 | 注明来源性质,降级表述 | 与一手样本数据混用计数 |
| 数据不足以回答 | "本次数据回答不了 xx" | 用推测填补 |

【待核对:完整证据强弱表和禁用词清单以方法论 v0.3 原文为准】

## 防编造

- **每条结论挂证据**:结论后面跟支撑它的类别/计数/原声引用(带原始链接)。挂不上证据的句子删掉。
- **引用必须真实**:所有原声引用必须从采回的数据里逐字取,不得改写、不得合成"典型用户会说"式的虚构引语。
- **数字必须可复算**:报告里每个数字都要能从 CSV 里算出来;写报告前用脚本重算一遍关键数字。
- **区分事实与解读**:报告结构上分开"数据显示什么"(事实)和"这可能意味着什么"(解读),解读段明确标注为解读。

## 报告结构

```
1. 一句话回答(或探索式:主要发现候选清单)
2. 取样说明(照抄方案:范围、N、时间窗、"仅覆盖……")
3. 数据质量说明(照抄 quality-check 的保留点,如有)
4. 发现明细:每条 = 表述 + 计数 + 典型原声(带链接)
5. 数据说不了的部分
6. 建议下一步(探索式:待验证的问题清单)
```

顺序不可调:回答在前,限定条件紧随其后,不把免责声明藏在最后。
