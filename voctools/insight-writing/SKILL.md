# 洞察提炼与输出

从数据到结论的规矩。核心原则:**结论强度不得超过证据强度;数据说不了的,明确写"说不了"。**

## 入口条件

同时满足才进入本 skill:

1. quality-check 全量闸门判定为**可用**或**带保留可用**(不可用 → 退回,不写结论)
2. 方案里的产出形式是**发现或结论**

方案只要数据表的任务(达人清单、竞品账号表等),到 quality-check 结束,**不走本 skill**。给一张名单硬配一段"洞察"是画蛇添足。

## 输入

- `plan.md` —— 研究问题、判断标准或停止条件、取样说明、"答不了的部分"
- `quality.md` —— 判定和**保留点**(带保留可用时必须逐条进报告)
- `manifest.json` —— 溯源:数据来自哪个工具、什么参数、什么时候采的
- `processed/*.csv` —— 数据本身

## 编码聚类

对评论、帖子这类文本数据逐条打标归类。**编码结果必须落成文件**,不能只在推理里完成——否则后面的计数无法复算、抽检无法复现。

产出 `coded.csv`:原数据每行追加 `类别` 和 `编码依据` 两列,归不进的填 `未归类`;quality-check 标注过的广告/机器人/模板内容行填 `排除-营销`(不进任何类别计数,见"来源分级")。

编码维度以方案里声明的为准(痛点/需求 或 内容形式),不自行判断。

- **验证式**:按方案预写的判断标准里的类别归。归不进去的进"未归类"桶,**不硬塞**。类别不得中途新增——那等于改判断标准。
- **探索式**:开放式编码,类别从数据里长出来,边归边长。要求更严:
  - 类别定义随归随写,写进 `codebook.md`(类别名 + 一句话定义 + 纳入排除标准)
  - "未归类"桶必须保留并报告其占比。占比过高(超过三成)说明类别体系不合适,报告并建议重编,不要硬提高覆盖率
  - 完成后**抽 10% 复查归类一致性**,报告不一致的条数。不一致率超过 20% 判定编码不可靠,**修订类别定义后重编**——改的是定义,不是把条目硬塞进现有类别。
- **内容形式类研究**(研究"什么内容在火"而非"用户在抱怨什么"):编码维度换成形式和手法(内容结构、开头方式、标签组合),不是痛点分类。

每个类别的产出:类别名 + 定义一句话 + 条数 + 2-3 条典型原声(带原始链接)。

## 证据强弱与措辞挂钩

结论用什么措辞由证据强度决定,**不由叙事需要决定**:

| 证据情况 | 允许的措辞 | 禁止的措辞 |
|---|---|---|
| 样本内计数(有明确分母) | "样本内(N=xx),xx 类共 xx 条,声量最高" | 外推到"市场上""用户普遍" |
| 探索式发现 | "浮现出以下候选""值得进一步验证" | 任何结论式表述 |
| 少量原声(<10 条)支撑的观察 | "有个别用户提到" | "不少用户""普遍反映" |
| 来源集中(quality-check 标注过) | "主要来自 xx 社区/账号,其他来源未见" | 当作全样本共识 |
| 二手转述、检索所得 | 注明来源性质,降级表述 | 与一手样本混用计数 |
| 数据不足以回答 | "本次数据回答不了 xx" | 用推测填补 |

**禁用词清单**(出现即需降级或删除):普遍、大多数、显著、明显趋势、用户认为、市场需求是——除非有明确分母的计数支撑,且分母是本次样本。

**百分比使用规则**:只在分母是本次样本且已在同句写明时使用(如"样本内 120 条中占 35%")。不写分母的百分比一律禁止。

## 来源分级

同一条信息,来源不同,可信度可以差一个量级。写进报告的每条外部信息按下表定级,级别写在引用处。**只有 S2 可以进计数**:

| 层级 | 来源 | 允许用途 | 措辞要求 |
|---|---|---|---|
| **S1 供给侧运营痕迹** | waitlist、订单积压、售罄/补货记录、发货周期、更新日志 | 需求/热度的最强单点证据(行为不说谎) | 写明具体痕迹和出处,如"该商品页显示 6 周发货" |
| **S2 一手 UGC 样本** | 本次采集、每行可溯源到原始链接的帖子/评论/差评 | **唯一可进计数的层级** | 按证据强弱表 |
| **S3 官方一手发布** | 财报、招股书、官网数据 | 背景、交叉验证 | "据 xx 官方披露",并注明官方口径有立场选择性 |
| **S4 二手媒体/报告** | 媒体报道、券商/咨询报告 | 背景 | "据 xx 报道/报告",只作方向性表述 |
| **S5 营销与不可溯源内容** | 软文、SEO 聚合站、内容农场、来源不明的转述 | 仅当线索,不进报告正文 | 不引用;必须提及时标"未经证实" |

配套规则:
- 样本内被 quality-check 标注为广告/机器人/模板内容的行,编码为 **"排除-营销"**:不进任何类别计数,占比写进报告第 4 节
- 网页检索所得一律按 S3–S5 处理,**永远不与 S2 混入同一个计数**(research-planning "唯一必须拦的混用"在本环节的落地)
- 同一事实有多层来源时按最高层级引用,注明交叉验证情况

## 防编造

- **每条结论挂证据**:结论后跟支撑它的类别、计数或原声引用(带原始链接)。**挂不上证据的句子删掉**,不要保留"看起来对"的判断。
- **引用必须真实**:原声从 `coded.csv` 里逐字取,不得改写、不得合成"典型用户会说"式的虚构引语。引用要能在原数据里搜到。
- **数字必须可复算**:报告里每个数字都用脚本从 `coded.csv` 重算一遍再写入。不得手工估算或凭印象写。
- **区分事实与解读**:结构上分开"数据显示什么"(事实)和"这可能意味着什么"(解读),解读段明确标注为解读,且解读不得引入数据里没有的新事实。
- **保留点不得弱化**:quality.md 里的保留点原样进报告,不许改写成更好听的说法、不许省略、不许挪到末尾。

## 报告结构

产出 `report.md`,放在采集目录下。**六节顺序固定,不得调换**——限制放在发现前面,读者先知道数据边界,再看数据说了什么:

### 1. 任务概述
- 研究问题 / 探索范围:从 `plan.md` 复制,不改写
- 研究模式(验证式 / 探索式)、编码维度(痛点/需求 或 内容形式)
- 取样说明:平台、种子、时间窗、排序方式、实际样本量 N——即"本次发现只覆盖什么范围"

### 2. 数据质量与限制
- quality-check 判定(可用 / 带保留可用)
- 保留点:从 `quality.md` 原样逐条搬入
- 本次答不了的:从 `plan.md` 搬入,加上执行中新发现答不了的

### 3. 回答 / 发现
- **验证式**:逐条对照方案预写的判断标准,每条给三态判定——**支持 / 推翻 / 数据不足**,三态之外没有第四种写法。判断标准之外冒出来的东西不在本节写,放第 5 节并标注为解读——这是"判断标准预先注册"在报告端的落点,防止先有数据再圆结论
- **探索式**:候选发现清单,一律候选措辞,不写结论
- 每条发现后紧跟证据:类别 + 计数(分母同句写明)+ 1-2 条逐字原声(带原始链接)。措辞按证据强弱表和来源分级表

### 4. 类别分布
`coded.csv` 汇总表:类别 | 一句话定义 | 条数 | 占比(分母=本次样本,表头写明)| 典型原声(带链接)。
"未归类"和"排除-营销"的占比必须出现在表里。探索式附归类一致性抽查结果和 `codebook.md` 引用。

### 5. 解读(标注为解读)
数据可能意味着什么、建议下一步验证什么。不引入数据里没有的新事实,措辞不得超过第 3 节的证据强度。

### 6. 溯源
- manifest 摘要:工具、参数、采集时间、实际代价
- 过程文件清单:`plan.md` / `manifest.json` / `quality.md` / `coded.csv`(探索式加 `codebook.md`)/ `processed/*.csv`

### 交付打包

交付的不是一份 report.md,而是**报告 + 第 6 节列出的全部过程文件**打包给用户。理由:① 溯源要能落到文件,用户复核不靠信任;② 交付包在用户手里,后续复用与续查**不依赖平台文件空间是否跨会话保留**。
