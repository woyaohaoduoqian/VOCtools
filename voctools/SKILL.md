# 数据采集(社媒调研)

把用户的采集需求转成对采集工具的调用,并安全执行。本文件只定义与具体工具无关的纪律和流程;各采集工具(provider)的调用协议和能力规格在 `providers/` 目录下,**构造调用参数和提取字段时必须查对应 provider 的规格文件,不得凭记忆猜测**。

## 铁律(优先级最高,任何情况下不得违反)

1. **先试跑后全量**:任何组合首次采集,必须先跑小样本(条数见 provider 协议,通常 5 条),向用户展示样本数据 + 全量成本预估,**获得用户明确确认后**才能全量采集。
2. **禁止自动重爬**:采集失败或质量不达标时,只报告问题和可选处理方案,等用户指示。不得自行重试付费采集。
3. **成本必须先算后花**:任何付费调用前,按 provider 规格算出费用上限并告知用户。预计超过 100 条时额外提醒费用与耗时。
4. **不支持的组合直说**:所有 provider 规格里都查不到的「起点 × 内容类型」组合,明确告知暂未接入,不得硬凑。
5. **凭证不落地**:API token 等凭证不得写入任何输出文件、不得在回复中复述。

## 任务四元组

每个采集任务 = {起点 start, 平台 platform, 内容类型 content, 字段 fields}。

- 起点类型:`keyword`(关键词) / `hashtag`(话题标签) / `account`(账号) / `postUrl`(帖子或内容链接)
- 内容类型:`profile` / `post` / `reel` / `comment` / `followers` / `following`
- 字段分三档:`common`(常用,默认给) / `advanced`(高级,按需) / `debug`(调试,一般不给)

用户的模糊需求先落到四元组,再查能力。落不到的(比如要"转化率"这种平台不给的数据),直接说明拿不到。

## 能力查询与工具选择

1. 遍历 `providers/*.json` 里所有工具规格,收集命中 {platform, start, content} 的候选。
2. 多候选排序:① `common` 字段覆盖最多 → ② 单价低 → ③ 专用工具优先于 all-in-one → ④ 官方/可靠性高的优先。只取第一顺位。
3. 记录选中的 provider 和工具,采集完成后在结果说明中注明数据来自哪个工具、何时采集。

## 通用执行流程

```
需求 → 四元组 → 查能力(不支持则止) → 报字段选项和成本预估
→ 用户确认字段和条数 → 试跑小样本 → 展示样本 + 全量成本 → 用户确认
→ 全量采集 → 去重(按规格 idOf) → 字段提取与格式化 → 存 CSV → 交付
```

任何一步失败:停下,报告,等指示(铁律 2)。

## 结果处理约定

- **去重**:`profile` / `followers` / `following` 类内容按规格里的 `idOf` 字段去重;其余默认不去重。
- **默认排序**:profile→粉丝数、post→点赞数、reel→播放量、comment→点赞数,降序。
- **字段取值**:字段 `path` 为数组时是多重兜底,按序取第一个非空值;`join: true` 的数组字段用空格拼接;布尔值输出"是/否";对象数组取其文本代表(text / username / name / title)后用 " | " 拼接。
- 输出 CSV,UTF-8 带 BOM(Excel 直接打开不乱码)。
