# Provider:{名称}

一句话说明这是什么、数据从哪来。

## 1. 前置条件

列出全部必需条件,并写明获取方式与优先级。

**任一条件不满足 → 本 provider 本次不可用,在预检阶段排除,不要尝试调用。**

## 2. 调用契约

按 type 写对应内容:

- `rest_api` —— base url、鉴权方式、启动 / 轮询 / 取数三步的完整请求、超时与中止方式
- `mcp` —— 工具名(注明"以运行时实际注入为准")、调用顺序、参数来源
- `self_hosted` —— 启动命令、配置文件位置、输出位置、并发限制
- `browser` —— 目标页面、操作序列、反爬应对的边界

同时写明**输入构造规则**:占位符替换、批量判定、条数上限如何传递。

## 3. 代价模型

四项都要填,写"无"也要写出来:

- **金钱**:单价与计算公式,或"免费"
- **时间**:单次任务量级
- **账号风险**:是否需要登录、是否有封禁风险
- **合规**:工具许可证限制、平台 ToS 限制

任一项非零,执行前必须告知用户(SKILL.md 铁律 2)。

## 4. 能力来源

- `static` —— 规格文件路径,说明其字段含义和维护方式
- `runtime` —— 如何在运行时查询该工具自身的能力(查询顺序、返回什么)

## 5. 特有闸门

本 provider 强制的额外确认点(超出 SKILL.md 通用流程的部分)。没有则写"无,按通用流程"。

## 6. 失败模式

已知失败情形及**要报告什么**。处置一律是"停下 + 报告 + 等指示",此处只写清报告内容和可能原因。
